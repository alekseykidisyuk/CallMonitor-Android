CallMonitor Android — build #20 (пилот)
Версия: 2.2.0-callmonitor.20 / versionCode 220020

ЧТО ДОБАВЛЕНО
- Постоянная очередь новых завершённых SIM-звонков в отдельной SQLite-базе.
- Автоматическая отправка по Wi-Fi или мобильному интернету через WorkManager.
- Стабильный call_id и неизменяемая копия для повторных попыток.
- Проверка размера, SHA-256, структуры Ogg, CRC и двух каналов Opus.
- Доставлено только после HTTP 200/201 + ok:true + stored:true + тот же call_id.
- HTTP 401/403 приостанавливает отправку до исправления доступа; 409 требует проверки.
- Настройки сервера и видимая очередь: Настройки -> CallMonitor · отправка записей.
- Токен шифруется ключом Android Keystore; в APK и журнале его нет.

ПЕРЕД УСТАНОВКОЙ
Сохраните APK build #19 и архив его ключа. Дождитесь завершения текущего звонка.
Не удаляйте приложение: обновление сохраняет настройки и сопряжение ADB.
Приёмник 0.1.1 уже установлен. На сервере ничего переустанавливать не нужно.

УСТАНОВКА
1. Распакуйте папку CallMonitor_Android_Build20 из архива в:
   F:\WORK\Sensera\CallMonitor
2. Подключите телефон USB-кабелем к компьютеру, разрешите USB-отладку.
3. Запустите INSTALL_UPDATE.cmd из распакованной папки.
   Он проверит контрольную сумму APK и установит его через adb install -r.
   Удаление приложения, очистка данных и изменение pairing не выполняются.
   Если ADB не найден автоматически, укажите полный путь к adb.exe.
4. После сообщения PASS откройте CallMonitor на телефоне.

ПОДКЛЮЧЕНИЕ СЕРВЕРА (ОДИН РАЗ)
Откройте Настройки. Вверху появился блок CallMonitor · отправка записей.
Нажмите Подключить сервер. Оставьте:
  Адрес:    https://callmonitor.sensera.online
  Компания: pilot
  Устройство: redmi-note12-01
  Оператор: operator-01
Вставьте device_token (тот же, который прошёл Windows DIAG).
Нужен именно device_token, а не admin_token и не ключ подписи APK.
Нажмите Сохранить. С этого момента новые записи включаются в очередь.
Старые файлы автоматически не импортируются: уже отправленная с ПК запись
не должна появиться на сервере ещё раз под новым идентификатором.

ПРОВЕРКА НА ТЕЛЕФОНЕ
1. USB можно отключить. Убедитесь, что запись готова, как в build #19.
2. Выключите Wi-Fi и мобильный интернет.
3. Сделайте два коротких обычных звонка: входящий и исходящий.
4. Убедитесь, что оба файла доступны локально и в блоке отправки «В очереди: 2».
5. Включите интернет. Не нажимайте ручных кнопок отправки.
6. Ожидайте «Доставлено: 2». Android может отложить фоновую задачу: это не
   обещание отправки в конкретную секунду после включения сети.
7. Откройте серверный status.php с admin_token. Если до теста была одна запись
   и других новых звонков не было, calls_total станет 3.
8. Прослушайте оба новых локальных файла: обе стороны должны сохраниться.
9. Следующим отдельным тестом проверьте reboot с ещё одной ожидающей записью.
   Для восстановления самого recorder после reboot нужен доступный Wi-Fi,
   как и в build #19. После перезагрузки разблокируйте телефон.

При проблеме пришлите скриншот блока очереди и серверный статус.
Токены, архив ключа и содержимое полей токена не присылайте.

ОГРАНИЧЕНИЯ ПИЛОТА
- Проверяется на прежнем Redmi Note 12 с прежним цифровым stereo-профилем.
- Сервер принимает Ogg Opus stereo, 48 кГц, не более 100 МиБ на запись.
- Используется прежнее имя: YYYYMMDD_HHMMSS.mmm+TZ_in/out_номер.ogg.
  Произвольный изменённый шаблон, mono или AAC будут отмечены как отклонённые.
- Отсутствие EOS допускается профилем приёмника только для этого устройства;
  это не доказывает, что звонок записан целиком. Захват/encoder/EOS не изменялись.
- Локальный исходный OGG не удаляется модулем отправки. Не удаляйте его вручную
  до подтверждения доставки и оставьте прежний режим Local-only без автоочистки.
- После принудительного Force stop Android блокирует фоновые задачи до следующего
  открытия приложения. Очередь при этом остаётся на диске.
- Временная закрытая копия для повторов занимает дополнительное место и удаляется
  после подтверждения сервера. История call_id сохраняется для защиты от дублей.
- Полный автоматический сценарий на реальном телефоне должен пройти этот пилот;
  CI не подтверждает работу ограничений HyperOS вместо испытания на устройстве.
