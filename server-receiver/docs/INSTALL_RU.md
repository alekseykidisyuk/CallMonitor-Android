# CallMonitor Server v0.1.0 — установка

Пакет предназначен для первого развёртывания на callmonitor.sensera.online,
PHP 8.3, SQLite, HostGator/cPanel. APK build #19 не обновляется.

## Шаг 1 — загрузка и распаковка

В cPanel → File Manager откройте **/home1/sensera**, загрузите архив
CallMonitor_Server_v0.1.0.zip и нажмите Extract в **/home1/sensera**.
Не распаковывайте архив внутри public_html или callmonitor.sensera.online.

В архиве две папки:

- callmonitor.sensera.online — только временная страница установки;
- callmonitor_private — исходники сервера, шаблоны и Windows-проверка.

Также в корне архива лежит CallMonitor_INSTALL_README.txt с уникальным кодом
установки. Прочитайте его на своём компьютере; не отправляйте этот код в чат.
Публичные index.php, .htaccess и .user.ini появятся только после установки.
Установщик откажется перезаписывать отличающиеся существующие публичные файлы.
При такой ошибке остановитесь и сообщите только код ошибки.

Пакет рассчитан на ПЕРВУЮ установку. Не распаковывайте его повторно поверх
работающего CallMonitor: процедура обновления ещё не реализована.

## Шаг 2 — установка (после проверки распаковки)

Откройте https://callmonitor.sensera.online/callmonitor_install_v010.php.
Введите код установки из README, название компании и имя менеджера.
Нажмите «Установить сервер» один раз.

Успех: JSON с ok=true, status=installed, version=0.1.0.
Сразу сохраните полный ответ в отдельный локальный файл. В нём два секрета:

- admin_token — просмотр состояния всех компаний этого сервера;
- device_token — загрузка звонков конкретного телефона.

Они показываются один раз. В серверных конфигурации и базе остаются только
SHA-256 токенов. Не присылайте токены/полный ответ/скриншот с токенами в чат.
Для подтверждения достаточно сообщить status и version.
Первые идентификаторы: tenant_id=pilot, operator_id=operator-01,
device_id=redmi-note12-01.

Установщик создаёт:

- /home1/sensera/callmonitor_private/data/callmonitor.sqlite3
- /home1/sensera/callmonitor_private/audio/
- /home1/sensera/callmonitor_private/logs/
- /home1/sensera/callmonitor_private/tmp/
- /home1/sensera/callmonitor_private/config/config.php

После установки удалите публичный callmonitor_install_v010.php, загруженный
ZIP и CallMonitor_INSTALL_README.txt с сервера. Локальный архив сохраните.
Повторный запуск установщика после успеха блокируется автоматически.

## Шаг 3 — проверка сервера

Откройте https://callmonitor.sensera.online/health.php — ожидается ok=true.
Откройте https://callmonitor.sensera.online/status.php и введите admin_token.
Вначале calls_total=0, устройство redmi-note12-01 включено.
В отчёте телефоны маскируются. Доступ к отчёту — только по admin_token;
это административный доступ ко всем компаниям, не кабинет клиента.

Если health.php возвращает 500/HTML вместо JSON — пришлите код ответа и
скриншот без секретов. Проверим обработку .htaccess на LiteSpeed. Нельзя
переносить закрытую папку в web-root для исправления ошибки.

HTTPS проверяет сам PHP, заголовку X-Forwarded-Proto не доверяет.
При ошибке https_required на HTTPS сначала проверяем окружение, не отключаем
проверку вслепую. Force HTTPS Redirect можно включить после health-проверки.
Android должен обращаться сразу к HTTPS, без перенаправления POST.

## Шаг 4 — проверка реальной записи с Windows

Этот шаг выполняется после успешного health. Разархивируйте пакет также
на компьютере. Откройте callmonitor_private/windows и запустите RUN_SMOKE.cmd.

Скрипт попросит путь к ранее проверенному stereo OGG из build #19 и device_token
(ввод скрыт). Используйте короткий звонок до 20 MiB. Скрипт не обращается к
телефону: нужный OGG должен уже быть скопирован на компьютер через adb pull.

Если имя соответствует YYYYMMDD_HHMMSS.mmm+HHMM_in/out_номер.ogg, дата,
направление и номер берутся из имени. Иначе скрипт запросит их отдельно.
Неизвестный номер оставьте пустым.

Проверяются HTTPS health, отказ неверному токену, отправка реального OGG,
повтор того же звонка и конфликт с другим корректным тестовым OGG.
Тестовый OGG с синтетическим тоном используется только для запроса,
который обязан получить 409; новой записи он не создаёт.

Пришлите только CallMonitor_SMOKE_REPORT_*.json.
SMOKE_STATE_*.json содержит локальные метаданные: не присылайте его.
Повторный запуск использует прежний call_id для того же файла и устройства.
После теста проверьте status.php: этот звонок должен быть представлен один раз.

## Если ответ установки с токенами потерян

Токены нельзя прочитать из их хешей. Не удаляйте базу и не переустанавливайте
приложение. В cPanel Terminal, если он доступен, можно выпустить новые:

    php /home1/sensera/callmonitor_private/bin/manage.php rotate-admin
    php /home1/sensera/callmonitor_private/bin/manage.php rotate-device redmi-note12-01

Вывод содержит новый секрет, его нужно сохранить локально. Старый токен
сразу перестанет работать. Если Terminal недоступен — сообщите об этом;
будет нужен отдельный защищённый способ восстановления.

## Сопровождение и ограничения этой версии

- Первый серверный этап: приём и хранение. Android auto-upload, расшифровка,
  анализ, Telegram, кабинеты компаний и прослушивание через веб ещё не включены.
- Лимит одного OGG — 100 MiB (104857600 байт); это политика сервера, а не
  доказательство пропускной способности shared hosting. Начинаем с короткого
  звонка. Фактические ограничения времени/трафика HostGator проверяются живым тестом.
- Приёмник рассчитан на один завершённый stereo OGG Opus с mapping family 0.
  Mono, незавершённые, цепочечные и многопоточные OGG отклоняются. Если реальный
  файл build #19 отклонён, сначала изучаем его; аудиотракт #19 не меняем.
- Контроль структуры не заменяет декодирование и прослушивание. Определение
  LEFT=operator, RIGHT=client взято из профиля проверенного Redmi; сервер не
  способен сам доказать личности говорящих или правильность каналов.
- Локальное аудио не удаляется. На сервере пока нет автоматической очистки,
  общей квоты компании и полноценного rate limiting загрузок. Контролируйте
  дисковое место до подключения многих телефонов. Журнал ограничен 10 MiB/месяц;
  при достижении лимита новые диагностические строки не записываются.
- SQLite использует короткую транзакцию записи; перед ней выполняются hash
  и проверка OGG. При конкуренции или временной ошибке возвращается 503.
- Между файловой системой и SQLite нет общей атомарной транзакции. Используется
  постоянный путь файла, повторная проверка и восстановление при retry. Это
  покрывает сбой процесса между rename и commit, но не гарантирует выживание
  данных при аппаратном сбое диска/питания. Телефон должен сохранять оригинал.
- Сиротские файлы после прерванной отправки сохраняются до повторной загрузки;
  автоматическое удаление таких файлов пока не реализовано.
- Ротация/отзыв устройств доступны через bin/manage.php (CLI). Новый телефон
  требует собственной проверки каналов до использования.
- Live-проверка HostGator и реального OGG пользователя обязательна до build #20.

## Резервное копирование

При доступном cPanel Terminal:

    php /home1/sensera/callmonitor_private/bin/manage.php backup-db

Команда создаёт согласованную копию SQLite в private/backups через VACUUM INTO.
Это копия БД, не аудио и не config.php. Храните отдельно защищённую копию
config.php и audio/. Для полного согласованного снимка остановите отправку,
дождитесь завершения текущих загрузок, затем снимите БД и файлы. Не копируйте
работающую SQLite вручную, игнорируя её журнал. Автоматический backup/restore
и политика сроков хранения в этот выпуск не входят.
